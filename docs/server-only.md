# 서버 연결 단일화

앱은 기존 서버 연결 버전만 사용한다. 화면에서 Demo/Live/데모/실서버 배지와 개발자 설정 패널을 제거했고, 예전 `?demo` 주소와 `VITE_API_MODE=mock` 설정으로도 데모가 열리지 않는다.

## 수정 위치와 이유

| 위치 | 변경 | 필요한 이유 |
| --- | --- | --- |
| `src/api/index.ts` | HTTP 어댑터만 생성. mock 어댑터 import와 모드 분기, 어댑터 교체 함수를 제거 | 배지만 숨기면 환경변수에 따라 여전히 데모 응답을 쓸 수 있어 실제 호출 경로부터 고정 |
| `src/api/mode.ts`, `src/api/mode.test.ts`, `src/vite-env.d.ts` | 모드 선택 코드·테스트와 환경변수 타입 제거 | 종료한 데모 모드를 다시 선택할 통로와 설정 안내 제거 |
| `src/App.tsx`, `src/screens.tsx` | 설정 패널과 진입 배지, 데모 사진 목록·미리보기 제거 | 데스크톱과 휴대폰, 예전 데모 주소 모두에서 데모 도구를 노출하지 않음 |
| `src/store.tsx` | 데모 패널 상태, 사진 결과 선택, 가짜 사진 생성, 의도적 요청 실패 상태 제거 | 실제 사용자 사진과 서버 응답만 화면에 반영 |
| `src/features/localization/demoPhoto.ts` | 데모 JPEG 생성 코드 삭제 | 사용자 사진 업로드만 사용하므로 더 이상 필요 없음 |
| `src/i18n.ts` | 모드별 문구 선택과 모드 배지 문구 제거. 카메라 탭의 Live/라이브를 Camera/카메라로 변경 | 한국어·영어 화면 모두에서 버전 구분을 없애고 카메라 기능을 쉽게 설명 |
| `src/liveview.tsx`, `src/styles.css` | 센서 디버그 표시와 데모 전용 스타일 제거 | 사용자에게 개발용 수치와 데모 장식을 보여 주지 않음 |
| `playwright.config.ts`, `e2e/` | 데모 전용 E2E 제거. 카메라 E2E를 HTTP 경로로 이전. 모바일·데스크톱 진입 검사 추가 | 제거된 데모 대신 유지할 서버 연결 흐름과 과거 진입점의 동작을 검증 |
| `README.md`, `CLAUDE.md`, `docs/architecture.md`, `docs/ci-cd.md` | 실행 방법과 구조·검증 범위 갱신 | 예전 설정을 따라 데모를 실행하려는 혼선 방지 |

테스트용 `src/api/mockAdapter.ts`와 기존 단위 테스트는 유지한다. 이 파일은 앱의 API 진입점에서 가져오지 않으므로 사용자 앱의 실행 모드로 선택되지 않는다. 데모 정책을 선택하던 단위 테스트는 해당 구현과 함께 제거했다.

## 예상 결과

1. 일반 주소나 `/?demo`로 접속하면 같은 한길 시작 화면이 열린다.
2. Demo/Live 배지나 설정 패널 없이 시작하기를 누르면 `POST /api/v1/sessions`로 세션을 생성한다.
3. 채팅·사진 업로드·위치 확정·경로 안내는 기존 서버 API를 호출한다. 서버 연결 실패는 오류와 다시 시도로 처리하며 데모 응답으로 바꾸지 않는다.
4. 위치 확인 화면에는 실제 사진 업로드와 직접 선택이 남는다. 사진 인식 API가 503을 반환하면 기존 직접 선택 안내를 사용한다.
5. 경로 화면은 노선 보기 / 거리뷰 / 카메라 탭을 제공한다. 기존 카메라 영상과 방향 화살표 기능은 유지한다.
6. 처음으로 돌아가기와 언어 설정은 기존 왼쪽 위 메뉴에서 사용한다.

수정한 소스를 빌드·배포한 뒤 적용되는 결과다. 과거에 별도로 배포한 다른 주소의 데모는 그 배포 환경에서 따로 내려야 한다.

## 사용 기술을 이해하는 방법

- **React·TSX**: 화면을 컴포넌트 단위로 만든다. `DemoPanel`을 화면 트리에서 제거하면 그 패널과 진입 버튼이 렌더링되지 않는다. CSS로 숨기는 방식과 달리 버튼 자체가 만들어지지 않는다.
- **TypeScript**: 화면 상태와 API 요청의 자료 모양을 검사한다. 데모용 상태·함수·환경변수 타입을 함께 제거해 남은 코드가 종료된 기능에 의존하지 않게 한다.
- **어댑터 패턴과 Fetch API**: 화면 → store → `src/api` → HTTP 어댑터 → API 클라이언트의 순서로 서버를 부른다. 어댑터는 같은 호출 형식을 다른 구현으로 바꾸는 연결 부품이다. 이번에는 앱에서 실제 서버 구현만 연결했다.
- **Vite**: 개발 서버를 제공하고 배포 파일을 만든다. 기존에는 `VITE_API_MODE`를 읽어 구현을 골랐지만 이제 그 값을 읽는 코드가 없다. API 주소(`VITE_API_BASE_URL`)와 개발 프록시(`VITE_API_PROXY_TARGET`) 설정은 계속 사용한다.
- **i18n 문구 테이블·CSS**: `src/i18n.ts`에서 한국어·영어 텍스트를 관리하고 CSS로 모양을 정한다. 모드 문구와 전용 스타일을 정리하되 유지되는 사진 분석 화면과 오류 알림 스타일은 보존한다.
- **Vitest·Playwright·MSW**: Vitest는 함수와 API 계약, Playwright는 브라우저 화면 흐름, MSW는 테스트용 서버 응답을 담당한다. MSW가 테스트에서 응답하는 것과 사용자 앱이 데모 모드로 실행되는 것은 별개다.

## 검증 방법과 범위

`pnpm verify`는 헤더·lint·TypeScript·단위 테스트를, `pnpm build`는 배포 빌드를 확인한다. `pnpm e2e`는 한국어·영어 및 모바일·데스크톱에서 일반 주소와 예전 데모 주소를 검사하고 서버 세션 요청을 확인한다. 카메라 E2E는 센서 방향에 따른 화살표, 불안정·센서 없음 안내, 탭을 떠날 때 카메라 해제를 확인한다.

E2E 응답은 MSW로 재현한다. 실제 배포 서버의 가동 상태, 실제 AI 응답과 기기 센서 정확도는 이 검사만으로 확인되지 않는다.

## 이번 작업의 검증 결과 (2026-10-24)

- `pnpm build`: 통과.
- `pnpm exec tsc -p e2e/tsconfig.json`: 통과.
- `pnpm test:e2e --workers=2`: 20개 통과. Windows에서 자동 종료가 지연된 테스트용 Vite 서버는 프로세스 경로를 확인한 뒤 종료했다.
- `git diff --check`, 신규 파일 헤더 검사: 통과.
- 기본 `pnpm verify`: 445개 중 444개 통과. 수정하지 않은 `src/features/session/languages.test.ts` 1개는 이 PC의 Node 24가 `navigator.language=ko-KR`를 제공해 실패했다. `detectDeviceLang(undefined)`는 기본 인자를 적용하므로 브라우저 언어를 읽는데, 기존 테스트는 영어를 기대한다.
- `$env:NODE_OPTIONS='--no-experimental-global-navigator'`를 설정한 PowerShell 프로세스에서 `pnpm verify`: 헤더·lint·타입 검사와 단위 테스트 445개 모두 통과. 이 설정은 해당 검증 프로세스에만 적용했으며 앱의 언어 감지 코드는 수정하지 않았다.

테스트 응답은 MSW로 재현했다. 실제 운영 서버 검증과 배포는 수행하지 않았다.

이후 실제 로컬 프론트·FastAPI·PostgreSQL 연동도 확인했다. 결과와 화면 7장, 재실행·배포 절차는 [로컬 연동 확인 보고](local-integration-review.md)를 본다.
